# Triage

Use configured tracker operations and role mapping. Preserve two categories (bug/enhancement) and five triage states (needs-triage, needs-info, ready-for-agent, ready-for-human, wontfix). Exactly one category and one state apply; resolve conflicting states before mutation. Blockers and implementation completion are separate facts.

Every posted triage comment/issue starts with:
> *This was generated by AI during triage.*

## Discover

List unlabeled, needs-triage, and needs-info items with relevant new reporter activity, oldest first. Listing summaries support selection only. Include external PRs only when configured; explicitly named PRs can be inspected regardless of discovery filter.

## Evaluate a selected item

Read full body, comments, labels, author, dates, prior notes, and PR diff. For bulk work, do this per item; do not replace it with listing data. Resolve exact item identity through the tracker.

Read relevant code/domain decisions. Search for already implemented behavior by concept and active prior rejection records. A resemblance is not automatic rejection.

Perform bounded verification: reproduce reporter steps or check the PR's claimed behavior while preserving local work. Report confirmed, not reproduced under stated conditions, or insufficient information. Reuse this evidence if deeper diagnosing-bugs work follows; triage need not find a root cause.

Recommend category and state with evidence. Prepare the actual brief/comment/role changes. Respect explicit directions already given; ask only for a consequential unresolved decision or external action not authorized.

## Apply

- ready-for-agent: use [AGENT-BRIEF.md](AGENT-BRIEF.md), with blockers explicit.
- ready-for-human: same brief plus the actual human-only next action.
- needs-info: record established facts and specific unanswered questions; do not re-ask resolved points.
- wontfix already implemented: point to the existing behavior; never put it in rejection memory.
- wontfix rejected bug: explain the decision.
- wontfix rejected enhancement: use [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md).
- needs-triage: preserve partial findings.

Apply only authorized changes, remove conflicting state roles, and read back the result. Report partial mutations precisely. An explicit state override need not trigger a new interview; note missing brief/evidence without pretending it exists.
