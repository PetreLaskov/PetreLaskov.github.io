Matt Pocock skills: all 38 study chapters

For people designing agent skills, studying human–AI collaboration, or comparing instructions against evaluation evidence. Each chapter explains the original mechanism, questions its assumptions, proposes a refactor, and develops another skill.

Use the full interactive reader to compare source, refactor, diff, original proposal and evaluation side by side. These individual pages preserve the same chapter material and can be read without JavaScript.

  1. writing-for-agents

    Adopt behavioral pruning and context-pointer discipline; treat claims about leading words and negation as hypotheses to test. Original proposal: decision-preserving-compression.

  2. grilling

    Pilot dependency-aware interviews for consequential plans; measure user effort and later rework, not question count. Original proposal: reversible-bets.

  3. grill-me

    Keep a deliberate entrypoint for serious inquiry, with verified dependency loading and no automatic workspace creation. Original proposal: preference-probes.

  4. teach

    Pilot a dedicated learning workspace with a small baseline check, source-grounded lessons, and evidence of transfer; do not equate a polished lesson with learning. Original proposal: transfer-test.

  5. research

    Adopt bounded primary-source research with one delegation level, explicit unresolved claims, and a useful result file. Original proposal: evidence-fork.

  6. handoff

    Adopt targeted portable handoffs with explicit state and resolvable references; retain the temporary-file default without pretending it is durable. Original proposal: resume-check.

  7. prototype

    Adopt narrow prototypes for uncertainty discussion cannot settle; preserve runnable evidence and require a real user verdict on subjective choices. Original proposal: assumption-budget.

  8. wayfinder

    Use only when planning genuinely exceeds one session; keep destination, dependencies, claims, and user-owned decisions explicit. Original proposal: stop-rule.

  9. to-spec

    Pilot for work spanning sessions; preserve exact decisions, confirm only unsettled test seams, and keep readiness distinct from execution. Original proposal: intent-examples.

  10. domain-modeling

    Pilot where ambiguous domain words cause real mistakes; keep the glossary small, context-specific, and separated from implementation decisions. Original proposal: boundary-cases.

  11. wait-what

    Adopt a tiny explicit repair command; judge restored comprehension rather than word count. Original proposal: contrastive-explanation.

  12. grill-with-docs

    Pilot for repositories with unsettled language; distinguish glossary, durable decision, and temporary discussion. Original proposal: decision-thread.

  13. loop-me

    Interview the user about recurring work and maintain implementable workflow specifications in a stateful workspace. Original proposal: workflow-payback.

  14. retro

    Review an actual coding session and recommend targeted improvements to navigation, checks, instructions, and information access. Original proposal: instruction-ablation.

  15. to-tickets

    Preserve tracer-bullet slices and the wide-refactor exception; add discriminating acceptance, true blocking semantics, and resumable publication. Original proposal: design-the-learning-sequence.

  16. diagnosing-bugs

    Keep the exact-symptom red loop as the core gate; distinguish harness construction from confirmed explanation and calibrate activation and stochastic evidence. Original proposal: construct-a-counterexample.

  17. code-review

    Preserve independent Standards and Spec axes; make the reviewed artifact explicit, prevent recursive delegation, and verify actionable findings. Original proposal: test-the-oracle.

  18. tdd

    Retain vertical red-green slices, independent expected values, and agreed behavioral seams; calibrate whether a test earns its cost and explain seam choices. Original proposal: change-the-representation.

  19. implement

    The very short source correctly trusts settled work; a portable version needs exact ticket identity, review of the actual patch, and evidence-backed completion. Original proposal: finish-the-last-mile.

  20. writing-fragments

    Mine heterogeneous writing fragments through conversation without prematurely imposing an outline. Original proposal: anchored-variation.

  21. writing-shape

    Shape a fixed body of raw material into a separate article through deliberate paragraph and format choices. Original proposal: thesis-stress-test.

  22. writing-beats

    Build an article one chosen beat at a time while tracking the concepts each beat requires and establishes. Original proposal: reader-state-simulation.

  23. to-questionnaire

    Adopt for a decision blocked on another person's knowledge; preserve one recipient, a flat fillable document, and no automatic sending. Original proposal: answer-reconciliation.

  24. scaffold-exercises

    Create or renumber course exercise skeletons that follow the repository conventions and pass its actual structure checks. Original proposal: misconception-lab.

  25. codebase-design

    Depth is caller leverage, not code volume; retain the glossary and alternative designs while making costs and reference-only scope explicit. Original proposal: rehearse-the-next-change.

  26. improve-codebase-architecture

    A visual survey of evidence-backed deepening candidates should be allowed to conclude there is no worthwhile refactor and should stop before unchosen design work. Original proposal: subtract-a-dependency.

  27. ask-matt

    A compact map is valuable when it recommends the next justified step without silently becoming an executor; routing claims need the actual target skill. Original proposal: find-the-binding-constraint.

  28. setup-matt-pocock-skills

    Repository-local prose configuration is a good indirection point; setup must target the active harness, verify capabilities honestly, and preserve existing decisions. Original proposal: make-a-working-example.

  29. pr

    Write concise pull request bodies that explain changed behavior, show appropriate evidence, and identify concrete reversal costs. Original proposal: reviewer-rehearsal.

  30. triage

    Preserve canonical roles, full-context verification, durable briefs, and concept-level rejection memory; distinguish readiness, blockers, and evidence limits. Original proposal: find-the-unasked-question.

  31. resolving-merge-conflicts

    Trace each conflicting change to its purpose, preserve compatible behavior, and complete the operation without sweeping unrelated work into the commit. Original proposal: compose-two-plans.

  32. wizard

    Preserve the staged human-run procedure, repair input and completion handling in the shared helper, and make remaining storage and destination limits explicit. Original proposal: make-the-tradeoff-tangible.

  33. implement-spec

    Implement a ticketed specification on one integration branch by scheduling ready work and validating each integrated dependency. Original proposal: integration-contracts.

  34. claude-handoff

    Continue authorized work in a fresh background Claude session using a concise handoff grounded in durable artifacts. Original proposal: resume-probe.

  35. setup-pre-commit

    Integrate Husky and lint-staged with existing repository checks while preserving scripts, staged work, and usable commit latency. Original proposal: feedback-budget.

  36. git-guardrails-claude-code

    Configure scoped Claude Code git restrictions with an explicit distinction between enforceable permissions and a limited legacy command-pattern tripwire. Original proposal: reversible-operation-design.

  37. setup-ts-deep-modules

    Add dependency-cruiser rules for flat TypeScript package boundaries and verify allowed and forbidden imports across every importer root. Original proposal: contract-surface-audit.

  38. migrate-to-shoehorn

    Replace suitable TypeScript test assertions with intention-specific Shoehorn helpers while preserving fixture semantics and test coverage. Original proposal: fixture-truth.
