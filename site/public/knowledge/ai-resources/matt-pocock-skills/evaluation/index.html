How the 38 agent skills were evaluated

The development study retained 342 responses across 114 prompts. Refactors tied the source in 36 skill groups and scored lower in two. A strong no-skill control limits what can be credited to the skills. This is inspectable development evidence, not proof of general collaboration gains.

Evaluation protocol, version 1

This edition separates a reproducible development evaluation from a proven improvement in collaboration. The trial unit is a compact, text-only response to a realistic fixture. It is not a live repository task, an end-to-end hook test, a user study, or a statistical estimate of effectiveness.

Design fixed before candidate review

There are 38 source skills. Each has a normal case, a stress case, and a non-trigger case: 114 prompts per condition. The coordinator wrote the prompts and observable assertions from the source purposes and likely failure modes before reading candidate drafts. The lock file records SHA-256 hashes. These are development cases, not a secret held-out benchmark: authors can technically read the shared filesystem, and an author reported one source mismatch before the lock. We do not claim airtight blinding.

Two fresh evaluator agents receive the same prompts and different skill collections, one source and one refactor. Neither receives chapter analysis, rubrics, the other condition's outputs, or intended answers. Source wrappers receive their available source dependencies. Refactored wrappers receive their corresponding candidates. Each evaluator performs the requested response under fixture constraints, rather than predicting whether the skill would work. Outputs are retained verbatim in JSON with case ids and candidate hashes. Cases share an agent context within a condition, so cross-case effects remain possible. The task context and host model are inherited from the executing session; no model-version, temperature, or seed control is asserted.

Scoring

The coordinator judges each frozen assertion against actual output: pass (1), partial (0.5), fail (0). Quote evidence for partial/fail and explain the governing behavior. Report paired case results, ties, and regressions; no significance test or universal percentage-improvement claim is warranted. A case is clean only when all its assertions pass. Unauthorized mutation, fabricated execution, or replacement of user scope is a critical failure even if other criteria pass. A text response proposing an operation is not evidence that operation ran.

Per-skill development grade is case-bound: A = all normal/stress assertions pass and non-trigger passes; B = no failed assertion, but at least one partial; C = one or more failed assertions with no critical failure; D = critical failure. This rubric measures the supplied response only. It is not a score for Matt, a proof of transfer, or a certification of the package.

Revision and evidence integrity

Keep first-trial outputs and the tested hashes. If a failure warrants an edit, retain a revision record and run a targeted follow-up with a fresh or explicitly identified continuing evaluator. Never silently replace first-trial results with a repaired draft. A changed candidate is untested until its corresponding follow-up is recorded. New original skill proposals receive independent critical review and clearly scoped smoke evidence where possible, not borrowed grades from their source's tests.

Beyond this edition

Before treating a candidate as a superior daily default, compare it with both the source and no-skill behavior on unseen real tasks, rotate evaluators, repeat runs, record user corrections, task success and attention/time cost, and test actual environment integration. Same-family agents and coordinator-designed rubrics can agree for the wrong reason. Keep the shorter source when the extra instructions do not earn their cost.

Before-trial protocol addendum: no-skill control

A third fresh evaluator will receive the same 114 fixture prompts without any skill package. It will not receive rubrics or source/candidate outputs. This control tests whether apparent improvements are already available from ordinary model behavior. It was added before any behavioral trial outputs existed; case prompts and their original lock are unchanged.

The added condition does not solve cross-case context contamination, one-run uncertainty, prompt cueing, same-family model bias, or the lack of real tool execution. If results saturate, report that limitation rather than assigning causal credit to the refactor. Original proposals receive a separate critical review; their status is not inherited from their source skill's grade.

How to interpret the result

This suite tests whether a model can produce an appropriate compact response under explicit fixture constraints. Many prompts make the desired boundary clear. It is therefore vulnerable to ceiling effects and cannot establish whether a skill changes long-running tool use, recovers from environmental failures, improves user attention, or reliably activates at the right time. A strong control result is evidence that those answers cannot be credited to the supplied skill alone.

The refinements remain design bets until unseen practical tasks demonstrate benefit. Prefer fixes with a concrete mechanism and documented source mismatch, but do not turn that judgment into an unsupported performance claim. No skill was globally installed or endorsed by the user.

The letter rubric is A = every assertion passes; B = partial support without any failed assertion; C = a failed assertion without a critical failure; D = a critical failure. Scoring is judgment-based, uses one response per case/condition, and was not statistically calibrated. Assertions should be contested where the retained response supports a different reading.

What the misses changed

The refactors lost half a point each on writing-beats and setup-matt-pocock-skills. The former carried unsupplied story context into a stress response; the latter imposed unverified tracker details. These are small observed regressions, not proof that either complete package is worse. The control also matched most cases. No result justifies a universal claim that longer instructions are better.

The setup seed received a concrete preservation repair. Writing-beats already forbade invented prerequisites, so its instructions stayed unchanged and an isolated retest was run. Triage and wizard received separate repairs from semantic audit. Initial grades remain attached to their tested versions.

The hook stress assertion about prompt advice was only partly supported by every condition: all clearly distinguished copied settings from enforcement, but none explicitly discussed prompt advice. This is partly a rubric-specific wording demand absent from the prompt, and should not be treated as evidence of differential skill value. The judgment is retained rather than altered after seeing results.

Eight targeted follow-up responses supported 24/24 assertions. Wizard regression tests passed 14/14 on the repair against 4/14 for source and v1. Original-hook classifier tests met 6/11 intended classifications. None of these later development checks removes the need for unseen practical tasks.

Execution notes explain grading and version handling. Published candidate identity maps final bytes to tested or repaired versions.

Independent reviews and revisions

Two agents inspected the complete collection independently of the chapter advocacy. One compared all 38 source/refactor packages and support files; the other read all 38 original proposals. These were design reviews, not live workflow tests.

The initial semantic audit found 31 clear, 5 deliberate tradeoffs, and 2 repairs. Both repairs were implemented with the initial candidates preserved: triage regains authorized closure; wizard fixes required-input and completion behavior. The wizard regression results distinguish the repaired helper from the text trial of its first version.

The response trial found a third concrete repair: the setup seed could override an existing tracker layout. Its final text gives observed conventions priority and receives a targeted follow-up. Writing-beats also lost partial credit for unsupplied story assumptions; its unchanged instructions receive an isolated retest, while the original score remains visible.

The original-portfolio audit recommended 26 pilots, 8 merges, 2 repairs, and 2 deferrals. This is a useful challenge to the idea that 38 proposals should mean 38 installations. Two overlapping proposals were replaced with preference-probes and anchored-variation. Instruction-ablation and thesis-stress-test received consequential validity repairs. The remaining merge/defer judgments remain visible in each chapter rather than being edited into universal praise.

Portfolio judgment

Verdicts: 'pilot' means the design has a sufficiently concrete mechanism to justify a bounded behavior test, not that it is proven valuable or should immediately be installed. 'merge' means preserve useful mechanisms inside a clearer family. 'repair' means fix a consequential validity defect before interpreting a pilot. 'defer' means the text is sound guidance but a separate skill has not yet earned its routing and context cost.

The portfolio is strongest where it forces an inspectable contrast: test-the-oracle compares correct and deliberately wrong behavior; resume-probe checks a fresh receiver's artifact-grounded next action; reviewer-rehearsal reconstructs a PR's meaning; rehearse-the-next-change exposes actual obligations under competing designs. These mechanisms can reveal something a fluent explanation alone cannot. They deserve early pilots, along with integration-contracts and decision-preserving-compression.

Thirty-eight source mappings do not justify thirty-eight separately installed skills. The clearest duplicate pairs are counterexample-search/construct-a-counterexample and counterimage/thesis-stress-test. Fixture-truth fits as a diagnostic mode in test-the-oracle. Boundary-cases fits as a classification mode in intent-examples. Consolidation should preserve the stronger local details rather than merely deleting one file.

An uncertainty-to-action family would make routing clearer: assumption-budget selects consequential unknowns; evidence-fork chooses a discriminating observation; reversible-bets designs a sustained reversible trial. Find-the-binding-constraint and find-the-unasked-question are useful entry modes for stalls and framing defects. The first three represent different stages; the latter two do not need competing generic diagnostic identities.

The learning family contains legitimate separable outputs: design-the-learning-sequence orchestrates adaptive practice, misconception-lab authors a diagnostic exercise, and transfer-test assesses application in a new case. Keep them callable at those different scopes, but share assessment principles. Likewise, resume-check validates changing external state while resume-probe tests successor comprehension; neither is a substitute for the other.

Most triggers include sensible exclusions and most procedures stop after a decision-relevant result. The broadest entries still overlap ordinary assistant duties: stop-rule and finish-the-last-mile chiefly encode completion hygiene; find-the-unasked-question can become routine reframing. Trigger testing should include nearby tasks where extra procedure would waste time, not only ideal prompts that explicitly ask for each named mechanism.

Observable artifacts are common, but outcome claims need stricter separation. A runnable example does not establish transfer; a comprehension question does not establish comprehension; a proposed next action does not establish successful continuation; a working interactive model does not establish better judgment. Reader-state-simulation and several fresh-agent probes already acknowledge this boundary. Pilots should preserve it in their reports.

The designs favor clarification, verification, counterexamples, and controlled repair. That is useful but narrower than a major expansion of collaborative capability: many are disciplined microprocedures for known good practice. The portfolio's ambition should be tested by what new usable work or better decisions it enables, not by the number of named thinking moves or the elegance of instructions.

Run a small first wave rather than all 38: choose mechanisms with clear artifacts and nearest-negative cases, preserve task context, compare against ordinary assistance, and count unnecessary questions, duplicate work, and time as costs. Instruction-ablation could support this only after its treatment-contamination defect is repaired. Do not interpret a successful static audit or a few rehearsals as general behavioral effectiveness.
