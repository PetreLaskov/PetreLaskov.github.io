# Make a Working Example

Choose the smallest example that teaches the consequential decisions.

1. Identify what a new collaborator needs to learn and the mistake the example should prevent.
2. Select a representative path with realistic constraints. Avoid a toy so simple it omits the hard distinction.
3. Produce the example artifact with input, expected result, and only the explanation needed to show why it works. Mark examples clearly so they cannot be mistaken for active work or real data.
4. Run or inspect it using the actual supported environment where possible. Record prerequisites and any unexecuted part.
5. Explain which parts are essential and which are incidental values the learner should change.
6. Ask whether the example enables an analogous task; if it merely encourages copying without understanding, revise the example.

Prefer one complete path over many fragments. Do not build a tutorial framework or duplicate the whole manual. For live services, use authorized fixtures or a documented dry run rather than creating sample production records.
