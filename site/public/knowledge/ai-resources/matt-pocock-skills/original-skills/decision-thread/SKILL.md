# Decision thread

Use when losing a decision's condition or exception during an artifact transition would change the work. Do not log every choice.

Select commitments at risk. Keep exact meaning, status (agreed, proposed, unresolved, superseded), and source. Preserve values, exclusions, ordering, and ownership. Include reasons only when needed to prevent misinterpretation.

At each requested transition, locate the commitment in the destination. Compare meaning, not keywords. A weakened requirement, changed default, or vanished exception is a loss.

Report losses with the smallest correction. Update authorized artifacts or provide the patch. Do not promote proposals or silently resolve conflicts.

Use a small table or existing issue section only when continuity needs an artifact. Link settled detail. Retire tracking when commitments are durably carried or work ends.

A test link identifies where behavior is checked, not proof the decision is correct. Inspect tests before claiming coverage.
