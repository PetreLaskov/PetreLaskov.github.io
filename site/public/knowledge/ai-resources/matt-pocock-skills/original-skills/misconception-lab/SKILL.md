# Misconception Lab

Use when creating or improving a learning exercise. State the capability the learner should demonstrate in observable terms. Identify one plausible wrong model that would produce a meaningfully different response. Use learner evidence when available; otherwise label the misconception as a hypothesis.

Build the smallest task that distinguishes the two models. Supply the information a learner should reasonably need and remove irrelevant setup. Avoid trick wording, hidden trivia, or examples that telegraph the correct answer. Decide what response would reveal the misconception and what would demonstrate understanding.

Create the learner prompt, minimal starting material, a worked solution, and a short diagnostic rubric. Explain the reasoning behind the solution, including why the plausible wrong approach fails. Keep the solution separate from learner-facing material when the delivery surface requires it.

Add one transfer variant that changes surface details while preserving the underlying principle. A learner who memorized the original example should not automatically pass. Do not add difficulty merely by increasing code volume or obscure terminology.

If possible, trial the exercise with an independent solver who has only learner-facing material. Observe ambiguity and unintended shortcuts; do not reveal the expected mistake. Revise based on actual responses and label simulated trials as such.

Deliver the exercise and the learning claim it can support. State what success would not prove. Fit an existing course structure when provided, but do not confuse a valid directory scaffold with a validated learning activity.
